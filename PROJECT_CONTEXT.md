## Project Overview

BananaCreat is a digital drawing and painting application for Android. The app allows users to create artwork with multiple layers, various brush types, and professional painting tools. The architecture separates concerns between the data layer, rendering engine, and UI, following MVVM patterns with Jetpack Compose.

**Target Platform:** Android 8.0+ (minSdk 26, compileSdk 34, targetSdk 34)  
**Language:** Kotlin  
**UI Framework:** Jetpack Compose  
**Build System:** Gradle (Kotlin DSL)

## Implementation Details

### Data Models

**ArtworkDocument**
- Composite bitmap rendering with layer support
- Layer management (add, delete, move, merge down)
- Properties: id, name, width, height, layers, activeLayerIndex, timestamps
- Automatic modification time tracking

**Layer**
- 18 blend modes (Normal, Multiply, Screen, Overlay, Add, Subtract, Hue, Saturation, etc.)
- Opacity, visibility, locking, mask support
- Bitmap-based storage with Canvas rendering

**BrushSettings**
- 10 pre-configured brushes (Round, Soft, Airbrush, Pencil, Ink, Marker, Flat, Calligraphy, Watercolor, Eraser)
- Parameters: size, opacity, hardness, spacing, pressure sensitivity, smoothing, scatter, angle, squish, jitter

### Rendering Engine

**BrushEngine**
- Generates brush bitmaps on-demand with caching
- Brush types: Round, Flat, Airbrush, Pencil, Watercolor, Marker, Ink, Calligraphy, Eraser, Smudge
- Pressure-sensitive size and opacity
- Supports brush angle, squish (aspect ratio), scatter, and jitter
- Radial gradient shaders for soft brushes
- Custom pencil texture and watercolor effects
- Eraser blend mode support

**StrokeProcessor**
- Smooth stroke interpolation with configurable smoothing
- Pressure-based rendering
- Flood fill algorithm with tolerance and safety caps
- Layer locking enforcement
- Undo/redo integration

**UndoStack**
- Bitmap-based snapshots (30-step limit by default)
- Separate undo and redo queues
- Per-layer history tracking
- Automatic cleanup on new strokes

### Data Persistence (DocumentRepository)

**Storage Format:**
- Base directory: `context.filesDir/artworks/{documentId}/`
- Metadata: `meta.json` (GSON serialization)
- Layers: `layer_{layerId}.png` (PNG compression)
- Thumbnails: `thumb.jpg` (256x256, JPEG quality 80)

**Operations:**
- `saveDocument()` - Persists all layers and metadata (IO dispatcher)
- `loadDocument(id)` - Deserializes document and layer bitmaps
- `listDocuments()` - Sorted by modification time (descending)
- `deleteDocument(id)` - Recursive directory deletion
- `createNewDocument()` - Factory for new documents with blank layer

### ViewModel (CanvasViewModel)

**State Flows:**
- `document` - Current artwork document
- `galleryItems` - List of saved documents
- `currentBrush` - Active brush settings
- `brushColor` - Current brush color
- `canvasVersion` - Invalidation counter for recomposition
- `canUndo` / `canRedo` - History state

**Key Operations:**
- `newDocument()` / `openDocument()` / `deleteDocument()` - Document lifecycle
- `beginStroke()` / `continueStroke()` / `endStroke()` - Stroke handling
- `undo()` / `redo()` - History navigation
- `setBrush()` / `setBrushColor()` / `setBrushSize()` / `setBrushOpacity()` - Tool config
- `fillLayer()` / `clearLayer()` / `floodFill()` - Layer operations
- `addLayer()` / `deleteLayer()` / `moveLayer()` / `mergeDown()` - Layer management
- `setLayerVisible()` / `setLayerOpacity()` / `setLayerBlendMode()` - Layer properties
- `exportPng()` / `exportJpeg()` - Export to file (quality configurable)

**Autosave:** 30-second interval autosave on document changes

## Architecture Decisions

### Bitmap-Based Rendering
- Each layer stored as a full-size ARGB_8888 bitmap
- Strokes drawn directly to bitmap via Android Canvas
- Composite created by layering bitmaps with blend modes
- **Pro:** Simple, fast for typical drawing use cases
- **Con:** Memory intensive for large canvases; no vector support

### JSON + PNG Persistence
- Metadata serialized with GSON, stored as JSON
- Each layer saved as PNG file in document folder
- Thumbnail generated at save time (256x256 JPEG)
- **Pro:** Human-readable metadata, portable format, easy recovery
- **Con:** Slower than binary format; PNG compression overhead

### Undo via Bitmap Snapshots
- Each stroke pushes a full layer bitmap snapshot
- 30-step history limit to manage memory
- **Pro:** Simple, works with any rendering approach
- **Con:** Memory intensive; no selective undo

### MVVM + StateFlow
- ViewModel manages all state and business logic
- StateFlow exposes immutable state to Compose
- Coroutines handle I/O and async operations
- **Pro:** Predictable, testable, Compose-native
- **Con:** Single ViewModel may grow large; no feature-based modularity

## Notes for Developers

- **Brush Cache:** BrushEngine caches bitmap dabs. Call `clearCache()` to free memory (already called in ViewModel.onCleared()).
- **Layer Locking:** Locked layers cannot be painted on; operations silently return. Add UI feedback for this.
- **Active Layer Index:** Always validate with `coerceIn()` after layer deletion to avoid IndexOutOfBoundsException.
- **Autosave:** Running in IO dispatcher; don't block main thread. Failures are logged but not surfaced to UI.
- **Large Bitmaps:** 2048x2048 ARGB_8888 bitmap uses ~33MB per layer. Be cautious with layer count or canvas size.
- **Blend Mode Support:** PorterDuff doesn't support all 18 modes; check `Layer.toXfermode()` for mappings.
- **Pressure Simulation:** Emulator doesn't provide real pressure; use `pressure` parameter for testing (0..1).
